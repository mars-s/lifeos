# Selected implementation contract

Use existing D1 operations and a small separate native overlay metadata table. Preserve all immutable historical payloads and final receipts. Add no general task authority database. New operations use cloud_wins only after the native v2 cutover flag is enabled. Existing things_wins operations retain their semantics.

Native pending GET returns sequence, revision (owner MAX operation ordinal), operations (next 20). Each operation includes ordinal. Native events WebSocket sends {version:1, revision:N}. Native uses existing X-LifeOS-Agent-Key header; no URL credential, redirects or browser Origin.

Owner Durable Object stores enqueue intents before D1 requests, plus recovery alarm. Serialize acceptance ordering: unresolved earlier enqueue cannot be overtaken by newer enqueue. Stable IDs and immutable request hashes are mandatory. Broadcast only durable committed revision. Retain latest revision after intent removal. No separate D1 notification outbox is required if these invariants are proved. Delivery alarms run only for outstanding work with connected sockets; disconnected catch-up reads revision on connect. No periodic native queue polling.

Persist maximum committed revision and remove resolved enqueue intent atomically. Unresolved enqueue recovery continues even without sockets. Only settled delivery retries stop when disconnected. Avoid first-20 executing claims starving later queued work: return queued work first or provide cursor/exclusion, and explicitly stop drain when blocked. Ack fence metadata is immutable per operation, including retries. Dedup cannot suppress a new causally required confirmation snapshot, even if content matches the previous hash.

For v2 receipts, ack body adds applied_after_sequence outside immutable result. Result stays state/reason only. For cloud_wins operations, result may add observed_before and verified_after cells ONLY if cloud worker/native writer tests agree on exact schema; prefer separate ack audit metadata to keep result unchanged. Before execution, capture journal.sequence for causal fence. Native manifest adds seen_cloud_revision captured before inventory read. Every full snapshot retains exact retry bytes. Overlay retirement requires applied/satisfied, snapshot.sequence > fence, seen_cloud_revision >= operation.ordinal, and matching observed value. Latest active overlay per target+field, complete query independent of pending/recent limits.

Sync engine serializes automation. Retain cloud/local dirty triggers while busy. Drain queue pages before new inventory. Flush durable pendingUpload exact bytes safely, never regenerate. Persist semantic inventory hash, excluding observation timestamp, only on accepted snapshot. Queue notifications cause target apply before full read; unchanged local events do not upload. Startup/wake/network/manual reconnect reconcile once. Backoff is one-shot for actual failures. Local midnight/timezone changes invalidate locally.

Bulk public reader preserves current v2 coverage token, all canonical fields, complete membership and ordering, two matching passes, budgets and unknown/absent/unsupported cells. Provide new BulkPublicThings type in a separate Swift file, keeping Runtime.swift exclusive to native worker. Parent integrates adapter choice. New reader must beat old reader in complete live parity measurement before installation.

Native worker owns event watcher in separate Swift file: narrow Things storage directory metadata events only, no DB parsing, dropped events/root replacement explicit, debounce and retained events. Permission denial reports degraded state. No Python or 1Password runtime. No hidden polling fallback.

Interrupted cloud_wins title/completion setters recover through read-before-repeat idempotent convergence under the original durable claim. Trash membership is checked before target lookup; an already trashed target is satisfied without another delete. Never blindly repeat app.delete. Existing things_wins writing recovery remains uncertain, and old final receipts remain immutable.
